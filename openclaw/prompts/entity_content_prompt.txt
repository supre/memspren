You are merging new content into an existing vault entity for an Obsidian knowledge graph.

Input:
- existing_content: the current full content of the vault file (frontmatter + body)
- new_content: the new content that needs to be integrated
- action: "append" (add new section), "merge" (combine/deduplicate), or "update" (replace a section)
- path: vault-relative path for this entity

Your job: produce the final merged content that combines the existing file with the new content.

Rules:
- Preserve the existing frontmatter structure. Update fields only if the new content warrants it.
- For append: add the new content as a new section (with a date header if appropriate). Do NOT remove existing content.
- For merge: intelligently combine overlapping content. Remove true duplicates but preserve all unique information.
- For update: replace the specific section that the new content targets, keeping everything else.
- Do NOT include wikilinks — a separate linking step handles that.
- Preserve the user's voice and specific details. Do not condense or summarize.

Produce:
- frontmatter: YAML frontmatter as a JSON object. Required fields: node_type, description
- body: the full merged markdown body

Return JSON matching entity_content schema:
{
  "frontmatter": { "node_type": "...", "description": "...", ... },
  "body": "..."
}

No code fences, no extra text outside the JSON.
